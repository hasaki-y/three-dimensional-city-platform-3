# 3.0 分轮实施进度

更新日期：2026-10-10。依据用户提供的《三维城市空间分析平台_3.0修改计划.md》，本轮落实“第一轮：产品逻辑”。保留现有模拟数据；按清单要求，完成第一轮后先验收，再增加后续功能。

## 第一轮：已实现并进入验收

1. 底图：`useBaseMap.ts` 管理一个当前 imagery layer；`stores/map.ts` 保存底图类型与错误；右上角支持深色/浅色/影像。切换不销毁 Viewer 或业务图层。
2. 默认图层：只启用建筑；原始 POI、道路、水系默认关闭，关闭的辅助数据不请求。移除粒子叠加。
3. POI：原始数据和结果分别在 pois/poiResults 数据源，结果可拾取；API 与 PostGIS 导入统一 category，原始文件和总数不变。消防站/避难设施未收录时明确提示。
4. 附近设施：新增 `/api/v1/analysis/facilities`，最近 N 个/自定义半径两种模式；设置条件→地图点选→主动查询→独立图层与列表。
5. 空间分析入口：移除独立 KNN/Buffer 名称。底层 API 保留，以“附近设施查询”和“范围内建筑查询”呈现。
6. 应急流程：三种事件预设、自定义半径、多类设施、范围计数、每类最近资源、地图/图表/列表联动。更换参数、位置、任务和退出时取消旧请求、清理旧图形/统计。

提前落实的展示约束：真实地形不可用时禁用剖面；取消模拟高程回退；设施聚合仅在点数至少 30、相机高度超过 1800m 时启用；窄窗口支持收起结果面板。聚合 hover 组成说明仍留在第二轮。

## 验证记录

- Node API 测试：4 项通过。覆盖 BBOX、2.0 应急输入兼容、分类 nearest/radius、无数据类别、非法参数、多类别应急数量与范围一致性。
- TypeScript 类型检查通过。
- Vite 生产构建通过；仍有大型 bundle 提示，未以构建成功代替性能验收。
- 浏览器：最近 5 家医院返回 5 条按距离排列的结果；改为银行/1000m 后旧结果清除，重新提交返回 17 条；爆炸预设自动切换 800m 并选择三类资源，返回 853 栋影响建筑、20 个范围资源，缺失类别显示未收录；退出清空专题结果。
- 底图：发现 CARTO 默认地址返回 API Key 水印图片，改为 Esri 在线瓦片。最终深色、浅色、影像均在浏览器显示；建筑范围查询返回 375 栋后切换底图，列表计数和黄色高亮保留，退出后清理结果。
- PostGIS（后续补充）：已通过安装目录发现本机 PostgreSQL 16.4 / PostGIS 3.4.0，建立项目独立实例并完成真实接口、几何和三类 EXPLAIN 验证，见 [本机验收记录](PostGIS本机验收.md)。此前未在 PATH 中找到命令，不能据此判定未安装。

这些计数对应测试选点，换位置后会改变，不是固定产品指标。

## 手动复验顺序

打开页面→检查仅底图/建筑→依次切换三类底图→附近设施点选、提交→改变类别/模式检查旧结果清除→重选位置→应急三种事件及快捷半径→无资源类别与空选择校验→图表/列表/框选→切底图检查结果保留→退出清理→辅助图层开关→确认剖面禁用。
